# Plan 01-02: Minimal end-to-end pipeline — presentation model, slide walk, renderer, CLI

**Objective:** Cut the first vertical slice all the way through (decisions 5, 15): `OpcPackage` → `loadPresentation` (slide size, slide list) → minimal `SlideBuilder` (three-layer master/layout/slide walk, text boxes, pictures) → string-emitting renderer with hybrid positioning (absolute `.pp-el` boxes, semantic tags inside, viewport-scaling slides) → `scripts/src/index.js` `convert()` → `node scripts/pptx-to-html.js deck.pptx` producing a self-contained `deck.html`. Diagnostics channel + `--strict` CLI convention (research Q2 conventions). After this plan the converter runs on real simple decks; fidelity deepens in later plans.

**Standing rules** (same as 01-01): zero-dep (`node:` built-ins only), `node --test scripts/test/` to verify, EMU→px = `Math.round(emu / 9525)`, own code with `// Adapted from PPTX2HTML (MIT) …` credits, no scope beyond this plan.

Create `scripts/src/pptx/context.js` — the diagnostics channel adopted from upstream (`kinds: unsupported | approx | error | missing`):

```js
export class Diagnostics {
  constructor() { this.items = []; }          // { kind, msg, slide }
  add(kind, msg, slide = null) {
    if (!['unsupported', 'approx', 'error', 'missing'].includes(kind))
      throw new Error(`diagnostics: bad kind ${kind}`);
    this.items.push({ kind, msg, slide });
  }
  get hasErrors() { return this.items.some(d => d.kind === 'error'); }
  format() { return this.items.map(d => `${d.slide != null ? `slide ${d.slide}: ` : ''}${d.kind}: ${d.msg}`); }
}
```

`Presentation` shape (frozen interface — every later plan builds against it):

```js
{
  slideSize: { cx, cy, pxW, pxH },   // EMU + px (px = round(emu/9525)); default 9144000×6858000 (4:3) when p:sldSz absent
  slides: [Slide],                    // built eagerly, in p:sldIdLst order; each { partName, index (1-based), hidden, ...slide fields }
  masters: [Master],                  // { partName, theme, clrMap } — from p:sldMasterIdLst; EMPTY ARRAY tolerated (pptxgenjs decks still have them, but never assume)
  title: string,                      // docProps/core.xml dc:title || '' (core.xml optional)
  theme: Theme | null,                // first master's theme (diag.add('missing','no theme part') when absent)
}
```

Loader behavior:
1. `const presPart = pkg.xml(pkg.mainPart())` → `p:presentation`. `p:sldSz` → cx/cy attrs (`type` attr ignored for now — scale math handles any aspect).
2. Slide list: for each `p:sldId` in `p:sldIdLst`, `r:id` → `pkg.rels(mainPart)` → resolve → part name. **Robustness loop** (mirrors upstream): wrap each slide build in try/catch — on error, `diag.add('error', \`failed to load ${name}: ${err.message}\`, index)` and push a placeholder slide `{ partName: name, index, broken: true }` so slide numbering stays aligned; a deck must never fail to convert because one slide is corrupt.
3. Masters: `p:sldMasterIdLst` → rels → master parts; each master's theme via the master part's `.rels` (`relBy('theme', …)`); `p:clrMap` attrs captured as an object `{ bg, tx, ... }` (theme engine consumes it in 01-03; here just capture raw).
4. `docProps/core.xml`: read only if `pkg.has('docProps/core.xml')`; take `dc:title` text.
5. Hidden slides: `show="0"` attr on the slide's `p:sld` root → `slide.hidden = true`.

Slide *building* (the spTree walk) is task 2 — `loadPresentation` calls `buildSlide(partXmlRoot, ctx)` for each slide and merges the result. Keep this plan's slide model minimal; the signature is the contract:

```js
// scripts/src/pptx/slide.js (task 2)
export function buildSlide(sldRoot, ctx) -> {
  background: null | { solid: string },   // minimal: srgbClr hex only; full fill engine arrives in 01-03
  elements: [Element],                    // { layer: 'master'|'layout'|'slide', kind: 'sp'|'pic'|'grpSp'|'graphicFrame'|'cxnSp'|'placeholder', id, name, ph: {type,idx}|null,
                                          //   geom: { x, y, w, h, rot } in px, text: string (concatenated), image: { partName } | null }
  notes: null,
}
```

`ctx` is `{ pkg, diag, presentation, slideIndex, master, layout }` — one object threaded everywhere.

```js
export function buildSlide(sldRoot, ctx)

Three-layer stack (adapted from PPTX2HTML `scripts/src/pptx/slide.js`, MIT): resolve the slide's layout via the slide part's rels (`relBy('slideLayout', …)`); resolve the layout's master likewise (fall back to `ctx.presentation.masters[0]`). Walk, in order, master `spTree` elements, then layout `spTree` (skip master-layer when the layout sets `showMasterSp="0"`), then slide `spTree` (skip both layers when the slide sets `showMasterSp="0"`), tagging each produced element `layer`. Dispatch on element tag: `p:sp` (text/pic-less shape), `p:pic`, `p:grpSp` (emit as a container of child elements with `parentGeom` — full child-coordinate math arrives in 01-04; here just recurse and offset children by the group's own `a:off`), `p:graphicFrame` (emit `{ kind: 'graphicFrame', frameKind: 'table'|'chart'|'smartArt'|null, ... }` — content parsed in later plans; for now `diag.add('unsupported', 'graphicFrame content (later plan)')` only when it actually carries table/chart/dgm content), `p:cxnSp` (treat like `sp` with line geometry). `mc:AlternateContent` → prefer the `mc:Choice` containing `Requires` we understand, else `mc:Fallback` (helper `chooseAlternate(node)`).

Per-element extraction:
- `p:nvSpPr/p:nvPr/p:ph` → `ph: { type: attr('type', 'body'), idx: attr('idx', '') }`, else null.
- `p:spPr/a:xfrm` → `a:off`/`a:ext` EMU → px `{ x, y, w, h }`, `rot` attr (60000ths of a degree) kept raw as `rot`. Missing xfrm → all zeros + `diag.add('missing', 'shape without xfrm', slideIndex)` (PowerPoint tolerates these; so do we).
- Text (minimal for this plan): concatenate all `a:t` under `a:txBody` → `text: string`. Structure arrives in 01-04.
- Pictures: `p:blipFill/a:blip/@r:embed` → rels → `image: { partName }`.
- Background: `p:cSld/p:bg/p:bgPr` → if it holds `a:solidFill/a:srgbClr` → `background.solid = '#' + val`; anything else → null + `diag.add('approx', 'background style not rendered (fill engine later)')` only when a non-trivial background exists.

<!DOCTYPE html>

.pp-slide { position: relative; width: var(--pp-w); height: var(--pp-h);
  background: #fff; overflow: hidden; margin: 16px 0;
  transform-origin: top center; transform: scale(var(--pp-k, 1)); }
.pp-el { position: absolute; }
.pp-slide img { max-width: none; }
</style>
</head>
<body>
<div class="pp-viewport">
  ${slides joined by '\n'}
</div>
<script>
(function () {
  var fit = function () {
    var k = Math.min(1, (document.documentElement.clientWidth - 32) / W);
    document.querySelectorAll('.pp-slide').forEach(function (s) { s.style.setProperty('--pp-k', k); });
  };
  addEventListener('resize', fit); fit();
})();
</script>
</body>
</html>
```

(`W`/`H` are baked into the emitted script too — the scale factor preserves the slide aspect ratio at any viewport width; slide content never reflows because boxes are absolute.)

Create `scripts/pptx-to-html.js` — runnable with bare `node`, no install (decision 5; `--help` text is the contract):

```
Usage: node scripts/pptx-to-html.js <input.pptx> [options]

Options:
  -o, --output <path>  Output file (default: <input>.html). With --split: output directory
      --split          Emit one HTML file per slide + index.html into the output directory
      --slides <spec>  Convert a subset, e.g. "1,3-5" (1-based)
      --strict         Exit non-zero when ANY diagnostic was recorded
  -q, --quiet          Suppress the diagnostics listing on stderr
  -h, --help           Show this help
```

Exact behavior (conventions adopted from upstream's `bin/pptx2html.js`, MIT):
- `--split` is accepted but, in this plan, exits with a clear "not implemented until plan 01-06" error message and code 3 — the flag exists now so the CLI surface never breaks (decision 12 seam). Plan 01-06 implements it.
- Reads input with `fs.readFileSync` (any path), runs `convert()`, writes `fs.writeFileSync(output, html)`.
- Diagnostics always print to **stderr**, one line each via `diag.format()`, prefixed `pptx-to-html: `; `-q` silences the listing.
- Exit codes: `0` clean or diagnostics-without-errors; `1` any `error`-kind diagnostic (still wrote the HTML); `2` usage/IO errors (missing input, unreadable zip — print message to stderr); with `--strict`, ANY diagnostic → exit 1.
- Import via relative ESM path: `import { convert } from '../src/index.js';` — works from any cwd because Node resolves relative to the file, and the script never assumes cwd.
