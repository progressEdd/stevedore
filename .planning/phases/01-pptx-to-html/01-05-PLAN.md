# Plan 01-05: Tables, charts (minimal render + diagnostics), SmartArt (pre-rendered fallback)

**Objective:** Complete the decision-21 tiering for the structured-content kinds: **tables fully rendered** (merged cells, per-cell borders/fills, banding via `tableStyles.xml`), **charts parsed → minimal SVG render from cached values + `approx` diagnostics** (no axis-styling parity), **SmartArt rendered from the pre-rendered `dsp:` drawing when present, else placeholder + diagnostics**. Nothing here runs a browser or a charting library — charts are our own minimal SVG.

**Standing rules** (same as prior plans): zero-dep, `node --test test/`, own code + MIT credit comments, EMU→px `/9525`. Build against the fixed interfaces of 01-01…01-04 (`XNode`, `resolveColor`, `resolveFill`, `buildTextBody`/`renderText`, `Diagnostics.addOnce`).

Create `src/pptx/table.js` (adapted from PPTX2HTML `src/pptx/table.js` + `tablestyles.js`, MIT):

```js
export function buildTable(graphicFrameNode, ctx) -> Table
// locates a:tbl inside a:graphic/a:graphicData[@uri contains 'table']; returns null (no diagnostic) for other frame kinds
```

`Table` shape:

```js
{
  cols: [wPx, …],                     // a:tblGrid/a:gridCol@w (EMU->px), in order
  rows: [{
    hPx: number,
    cells: [{
      gridSpan, rowSpan,              // from a:tc@gridSpan/@rowSpan (default 1)
      hMerge, vMerge,                 // continuation cells -> boolean true
      fill: Fill|null,                // a:tcPr fill (resolveFill)
      borders: { l, t, r, b, tl2br, tr2bl },  // each { w, color, dash } | null from a:lnL/lnT/lnR/lnB/lnTlToBr/lnTrToBl
      marL, marR, marT, marB,         // a:tcPr margins EMU->px (defaults 91440/91440/45720/45720)
      anchor, vert,                   // a:tcPr@anchor/@vert
      text: TextBody,                 // buildTextBody on a:txBody (empty paragraphs OK)
    }],
  }],
  styleRef: { id, firstRow, lastRow, firstCol, lastCol, bandRow, bandCol } | null,   // a:tblPr@a:tableStyleId + flags
  style: TableStyle | null,           // resolved from ppt/tableStyles.xml when styleRef.id matches a:tblStyle@styleId
}
```

`loadTableStyles(pkg, diag)` (same module): reads `ppt/tableStyles.xml` if present, maps `styleId -> { wholeTbl, band1H, band2H, firstRow, … }` where each part holds `{ fill, borders }` resolved from `a:tableStyleId`'s `a:tblStyle` children. Style application precedence: direct `tcPr` beats style part; style part beats nothing. When `tableStyles.xml` is absent (pptxgenjs decks: common) → `style: null`, flags ignored, and no diagnostic (it is legitimate). Diagnostic discipline: diagonal borders → render nothing + `addOnce('approx','table diagonal borders not rendered')`.

Create `src/render/table.js`:

```js
export function renderTable(table, rctx, opts) -> string
```

Emit a real `<table>` (semantic, decision 15):

```html
<table class="pp-tbl" style="border-collapse:collapse;width:${sum(cols)}px;table-layout:fixed">
  <colgroup><col style="width:${w}px">…</colgroup>
  <tr style="height:${h}px">
    <td colspan="${gridSpan}" rowspan="${rowSpan}"
        style="border-left:${w}px ${dash} ${color};border-top:…;padding:${marT}px ${marR}px ${marB}px ${marL}px;
               ${fill?'background:'+fillColor:''};vertical-align:${anchor map};text-align:inherit">
      ${renderText(cell.text, …)}
    </td>
  </tr>
</table>
```

Rules: continuation cells (`hMerge`/`vMerge` true) emit NOTHING (the span origin cell carries `colspan`/`rowspan`); border sides with `none`/absent → `border-…:none`? — NO: absent border means "do not draw" (transparent): omit the declaration so `border-collapse` doesn't invent lines; `Fill` solid → background color; grad/patt fills → `background:` with a data-URI pattern via `svgPaint` output embedded as `background-image:url(data:image/svg+xml;base64,…)` (encode the mini-SVG defs with `Buffer.from(svg).toString('base64')`); text via the shared `renderText` with `titleLevel: 0`. Style-part fills for banding: apply `band1H`/`band2H`/`firstRow` fills when flags set and style present.

Wire into `src/render/slide.js` (modify): `graphicFrame` elements with `frameKind: 'table'` now render `renderTable(...)` inside their `.pp-el` box (the frame's `a:xfrm` off/ext position it); remove the 01-02 `unsupported: graphicFrame` diagnostic for the table case.

Create `test/table.test.mjs` with a `buildDeck` fixture carrying one graphicFrame table: 3×3 with `gridSpan=2` at row0col0, `vMerge` continuation at row1col1, a red `a:lnL` on one cell, `firstRow=1` + a tableStyleId present in an injected `ppt/tableStyles.xml`. Assert: HTML has `<table`, `<colgroup>` with 3 `<col`, the span cell has `colspan="2"`, the continuation cell emits no `<td>` (count `<td` = expected), red left border present as `border-left:`, banding fill applied to the header row from the style part, cell text rendered through the same run engine (`<span style=` present).

`Chart` shape:

```js
{
  kind: 'bar'|'bar3D'|'line'|'area'|'pie'|'doughnut'|'scatter'|'bubble'|'radar'|'stock'|'surface'|'combo'|'chartEx',
  title: string | null,              // c:tx//a:t concatenated
  plotGroups: [{                     // one per c:barChart/c:lineChart/… group (combo = multiple)
    kind: 'bar'|'line'|'area'|'pie'|…,
    barDir: 'col'|'bar',
    grouping: 'clustered'|'stacked'|'percentStacked',
    series: [{
      name: string,                  // c:tx//c:v
      cats: (string|number)[],       // c:cat//c:pt/c:v (strCache or numCache)
      vals: number[],                // c:val//c:numCache/c:pt/c:v
    }],
  }],
  axes: [{ orient, pos, delete, title, numFmt }],   // captured raw — parity not attempted
  legend: { pos } | null,
  unsupported: string[],             // collected feature names: trendlines, errorBars, dataLabels custom, secondary axes, 3D, ...
}
```

Every entry pushed to `unsupported` ALSO becomes `diag.addOnce('approx', 'chart feature X rendered without fidelity')`. `cx:chartSpace` (chartEx) → `kind: 'chartEx'`, everything else null-ish. Embedded `externalData` xlsx: never opened (cache only) — that IS the design (upstream reads caches too).

Create `src/charts/render.js`:

```js
export function renderChart(chart, rctx, opts) -> string
```

Minimal honest render (decision 21: "charts parsed → minimal render + diagnostics"):
- `bar`/`bar3D` clustered col: vertical bars per series grouped per category — plain rects in one inline `<svg viewBox="0 0 W H">` inside the frame box, series colors from a fixed palette `['4472C4','ED7D31','A5A5A5','FFC000','5B9BD5','70AD47']`, value labels omitted, axis lines omitted. Stacked variant: stack rects. `barDir:'bar'`: horizontal.
- `line`/`area`: polyline (path) per series, points evenly spaced across width; area closes to the baseline with 30% alpha fill.
- `pie`/`doughnut`: arcs per value share (`startAngle=-90°`, doughnut leaves a center hole `r*0.5`).
- `scatter`: circles at even x positions (x-values as ranks — `approx` diagnostic once: 'scatter plotted by rank').
- Everything else (`radar`,`stock`,`surface`,`bubble`,`combo`,`chartEx`) → a styled placeholder div: `<div class="pp-chart pp-chart-approx" style="…dashed border…">${title || 'Chart'} — approximated (${unsupported.join(', ')})</div>` + `approx` diagnostic.
- Always emit the chart title as `<div class="pp-chart-title">` above the SVG when present.
- Always emit `<div class="pp-chart-data" hidden>` containing `<table>` of cats/vals/series names — machine-readable data keeps the output honest while visuals are minimal (upstream parity target noted for a later phase).

<name>Task 3: Render SmartArt from the pre-rendered drawing, placeholder otherwise</name>
<files>src/pptx/smartart.js, test/smartart.test.mjs</files>
<action>
Create `src/pptx/smartart.js` (decision 21: SmartArt layout engine deferred; the `dsp:` pre-rendered drawing is the cheap full-fidelity path — PPTX2HTML `src/smartart/engine.js` is the reference for the LATER phase, not now):

```js
export function buildSmartArt(graphicFrameNode, ctx) -> { elements: Element[], title: string | null, approximated: boolean }
```

Algorithm:
1. Frame's rels → rel with type suffix `diagramData` → part `ppt/diagrams/data1.xml` (name varies; keep index).
2. From the **data part's** rels, look for `diagramDrawing` (`http://schemas.microsoft.com/office/2007/relationships/diagramDrawing`) → `ppt/diagrams/drawing1.xml`. (PowerPoint always writes the pre-rendered drawing alongside the data part when it saved the file.)
3. If found: parse `dsp:drawing/dsp:spTree` with the SAME element walker as slides — refactor the element-walk inner function of `src/pptx/slide.js` (the per-element dispatch `sp/pic/grpSp/...`) into an exported `walkSpTree(spTreeNode, ctx, layer)` in `src/pptx/slide.js` and call it with `layer:'slide'`, `ctx` carrying the drawing's own rels for `r:embed` resolution. The returned `Element[]` renders exactly like slide shapes (full fidelity for free).
4. If NOT found (diagram saved without a pre-render): `{ elements: [], title: <a:t of the first `dgm:pt` name if parseable>, approximated: true }` + `diag.add('unsupported', 'SmartArt layout engine deferred — pre-rendered drawing absent')`.
5. Wrap the returned elements in the frame's `a:xfrm` box (scale children from the drawing's own coordinates into the frame box proportionally — drawing `dsp:spTree` coordinates are already page-absolute in most decks; if any child falls outside the frame box by >10%, scale to fit and add `approx` diagnostic once).

Also export `export function smartArtTitle(dataXml)` — reads `dgm:pt[@type='doc']/dgm:t` text (the diagram title) for the placeholder fallback:

```html
<div class="pp-smartart-approx" style="border:1px dashed #999;display:flex;align-items:center;justify-content:center;height:100%;color:#666;font-style:italic">
  SmartArt: ${title || 'diagram'} — layout engine deferred
</div>
```

Wire into `src/render/slide.js` (modify): `graphicFrame` with `dgm` graphicData → `buildSmartArt` → either render its elements directly inside the frame box, or the placeholder.

Create `test/smartart.test.mjs`: fixture with `graphicData` diagram rel → data part → data-part rels → `drawing1.xml` containing one `dsp:sp` with text; assert the text appears inside the frame box with full shape rendering (`pp-el` + `pp-geom` svg), no diagnostics. Second fixture: data part WITHOUT the drawing rel → placeholder div contains `layout engine deferred` + one `unsupported` diagnostic.
