# pptx-to-html

<ROLE>
You convert .pptx decks to HTML. You run one command and read its
diagnostics; you never open PowerPoint.
</ROLE>

<WORKFLOW>
1. Locate the deck file (absolute path). If it is .ppt (OLE2), ask the user
   to re-save as .pptx — the converter rejects it with that exact message.
2. Run the conversion (paths relative to this skill's repo root — adjust the
   prefix to wherever the subtree lives):

   ```bash
   node scripts/pptx-to-html.js /path/to/deck.pptx -o /path/to/deck.html
   ```

3. Read the stderr diagnostics. `approx`/`unsupported` lines mean the HTML is
   complete but a feature was tiered down (see reference/fidelity.md) — report
   them to the user in one sentence; do not fail the task for them.
4. For multi-author decks or per-slide editing, also emit the split form:

   ```bash
   node scripts/pptx-to-html.js /path/to/deck.pptx --split -o /path/to/deck-dir/
   ```

5. Validate the output with reference/validation.md (slide count, spot-check
   first and last slide text, open in a browser).
</WORKFLOW>

<DESIGN_NOTES>
- Output is a single self-contained HTML file (inline CSS, data-URI images) —
  safe to attach, host, or commit.
- Slides keep PowerPoint's aspect ratio and scale to the viewport.
- Animations and transitions are recorded as embedded JSON data, not played.
</DESIGN_NOTES>

## Supporting Files

| File | Purpose |

| reference/usage.md | Full CLI reference: flags, exit codes, diagnostics kinds |
| reference/fidelity.md | What renders fully vs. approximated vs. deferred (tier table) |
| reference/validation.md | Post-conversion checklist and common fixes |
| examples/land-e/ | Worked pair: real 20-slide deck pptx + its converted HTML |
```

Create the three reference docs:
- `reference/usage.md` — the CLI contract copied from `scripts/pptx-to-html.js --help` output (run it and paste), plus the diagnostics kinds table (`error` = slide failed to load; `approx` = rendered with reduced fidelity; `unsupported` = deferred tier, placeholder emitted; `missing` = absent part tolerated), exit codes 0/1/2, and the `--slides 1,3-5` subset flag.
- `reference/fidelity.md` — the tier table, one row per kind: Fully rendered (text + inheritance, fills/gradients/patterns, 40+ preset geometries, pictures + crop, tables, groups/connectors, notes/sections/hidden, timing+transitions as JSON) / Approximated (charts → minimal SVG from cached data, exotic geometry presets → bbox, compound lines, scatter by rank, vertical-text variants) / Deferred (EMF/WMF, TIFF, EOT fonts, SmartArt layout engine without pre-rendered drawing, animation playback, 3D). State plainly: parity target is PPTX2HTML's feature set, staged across phases.
- `reference/validation.md` — checklist: exit code 0; slide count equals PowerPoint's; first/last slide text spot-check; grep a known word from an interior slide; `--strict` run documents the full approx list; split-mode index links resolve. Common fixes: .ppt → re-save; fonts look wrong → deck uses embedded EOT fonts (deferred tier); chart looks plain → cached-data render by design.

Every doc states paths relative to the skill root and notes the subtree prefix adjustment once at the top of usage.md.

pptx ↔ HTML conversion skills — the inverse pair to dom-to-pptx.

  (agent skill: SKILL.md + CLI). **Ready.**

## Convert a deck (zero dependencies)

Requires Node ≥ 18. No npm install — ever:

    node scripts/pptx-to-html.js path/to/deck.pptx -o deck.html

Options: `--split` (per-slide folder + index.html), `--slides 1,3-5`,
`--strict` (fail on any diagnostic), `-q`. Diagnostics print to stderr and
list every approximated or deferred feature. See
`skills/pptx-to-html/reference/usage.md`.

## Consume via git subtree

From your repo:

    git subtree add --prefix vendor/stevedore <this-repo-url> progressEdd

Then run `node vendor/stevedore/scripts/pptx-to-html.js deck.pptx`.
Pull updates with `git subtree pull --prefix vendor/stevedore <url> progressEdd`.

## Layout

- `scripts/` — runnable CLIs (`pptx-to-html.js`)
- `src/` — converter library: `opc/` (zip+content-types+rels), `pptx/` (model
  builders), `geometry/`, `charts/`, `render/` (string emitters), `util/`
- `skills/` — agent skills
- `test/` — `node --test` suites; fixtures are generated, not committed binaries

## Credits

This is our own implementation. Logic in specific spots is adapted from —
and credited inline in the source next to — these MIT-licensed references:

- [PPTX2HTML](https://github.com/g21589/PPTX2HTML) (commit c8a96eb) —

License: GPL-2.0-only (see LICENSE).
