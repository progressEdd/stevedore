```js
// (02-05) a:videoFile r:link — the pic is a video; blip stays as poster
const videoFile = node.path('p:nvPicPr/p:nvPr/a:videoFile');
if (videoFile) {
  const rid = videoFile.attr('r:link');
  const rel = rid && ctx.pkg?.rels(ctx.partName)?.find(r => r.id === rid);
  if (rel && !rel.external)
    image.videoPart = ctx.pkg.resolvePartName(ctx.partName, rel.target);
  else if (rid)
    ctx.diag.add('missing', `video rel ${rid} not found`, ctx.slideIndex);
}
```

(Insert before the existing embed resolution so `finishImage`'s srcRect/crop handling still applies to the poster; keep the existing `image.partName` poster resolution unchanged. **Render side — `scripts/src/render/slide.js`, the `if (el.image)` branch (~line 74):** when `el.image.videoPart` is set, emit a playable video instead of a bare `<img>`:

```js
if (el.image.videoPart) {
  const type = rctx.pkg.mimeOf(el.image.videoPart);           // 'video/mp4' via util/mime.js
  const poster = el.image.partName ? ` poster="${rctx.url(el.image.partName)}"` : '';
  inner = `<video class="pp-video" controls${poster} style="width:100%;height:100%;object-fit:contain">` +
          `<source src="${rctx.url(el.image.videoPart)}" type="${type}"></video>`;
}
```

(`rctx.url()` already data-URI-encodes any part with its sniffed mime — mp4 is known to `util/mime.js` — so the bytes land base64 in the HTML, which is exactly what the survival gate scans for.)
